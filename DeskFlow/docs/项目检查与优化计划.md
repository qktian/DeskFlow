# DeskFlow 项目检查与优化计划

日期：2026-10-04。范围：当前仓库的 Core、Shell、App、需求文档与构建结果。

## 当前定位

产品已从桌面整理扩展为「桌面文件分组 + 待办清单」。适合继续围绕这两个高频场景完善。
底层是 .NET 8 / WPF，WinForms 负责托盘，Win32 / COM 提供 Shell 能力。三个生产项目未声明第三方 NuGet 包依赖。
归类保存路径引用，不搬迁文件；用户明确执行重命名、删除或向外拖放则可能改变真实文件。

三层结构清楚，但窗口后台仍承担大量业务逻辑。复杂度集中在图标提取、盒子交互、待办渲染和设置事务。
本轮优先修复可复现的问题并补充回归工具，没有整体重写窗口架构。

## 本轮修复

| 类别 | 原有问题与影响 | 处理 |
|---|---|---|
| 图标显示 | Kenshi 快捷方式在 256px 画布内只有约 48×44 图案，缩到 48px 后只有约 9×9 | 仅对显著过量留白裁剪，保留少量边距、比例及 DPI |
| 图标透明度 | 预乘像素直接传给 GDI+，重新预乘时可能使边缘发暗 | 转换到明确的直通 BGRA，重采样结果按已知格式预乘 |
| DPI 缓存 | 相同物理像素、不同逻辑尺寸共用缓存 | 缓存键增加 DPI；回调校验列表代次，丢弃旧请求 |
| 资源生命周期 | 快捷方式解析 COM 对象未显式释放，失效队列仍可能回填旧图标 | 释放局部 COM 对象和后台图像列表；失效请求不再写回；重复 Dispose 安全 |
| 本地文件操作 | 重命名允许相对/绝对路径，可意外把文件移动到其他目录 | 限制为合法叶子文件名，拒绝路径分隔符、设备名和无效结尾 |
| 文件归属 | 重命名清掉手动分类；桌面外引用可能消失 | 迁移旧/新路径及目录下引用，保留手动与排除标记 |
| 删除反馈 | 忽略系统删除返回码，失败仍清除模型记录 | 失败显示错误，取消/失败不移除记录 |
| 持久化 | 直接覆盖配置，损坏主文件可污染备份，保存异常静默 | 同目录临时文件 Flush 后原子替换；备份仅取有效主文件；保存失败返回结果并提示 |
| 配置健壮性 | null 集合/元素、循环父子任务可能导致异常或递归问题 | 加载时归一化集合，修复任务重复 ID、循环与过深父链 |
| 自定义规则 | 新规则排在默认规则后，常见类型无法覆盖默认分类 | 新规则排在前面，优先级重新编号避免整数溢出 |
| 归类性能 | 每个文件重复建立规则匹配顺序 | 每批一次排序，保持首个命中语义 |
| 监听性能 | 文件修改就全桌面扫描、所有盒子刷新，连续事件可能一直等待 | 按变化路径增量处理、仅刷新受影响盒子；700ms 批处理窗口，溢出时全量补扫 |
| 批量操作 | 每拖入一个文件就刷新和保存一遍 | 一批路径一次刷新和保存 |
| 保存性能 | 无配置变化仍重写主文件与备份 | 序列化内容相同则跳过写入，仍保留内容比对开销 |
| 待办状态 | 长期运行跨天后显示过时，副屏断开没有回收面板 | 每分钟刷新时间状态，重新显示时立即刷新，屏幕变更时调整待办位置 |
| 设置事务 | 取消没有立即写回，窗口关闭不走相同回滚路径 | 关闭/取消统一回滚并保存，重新应用系统设置 |
| 热键 | 大写 O 经 VkKeyScan 被当作 Shift+O | 字母直接映射虚拟键，显式 Shift 仍保留 |
| 桌面图标 | 隐藏重试可能在用户显示图标后继续运行；Explorer 未就绪被当成隐藏成功 | 同一 Dispatcher 上执行可取消的重试；未找到桌面窗口返回失败 |
| 退出指令 | 没有实例时 --exit 可能启动正常应用 | 无实例退出请求直接退出，释放退出信号句柄 |

这里的文件名问题属于本地操作边界缺陷，不是已证明的远程入侵漏洞。
本轮是源代码检查与定向测试，不代表全面渗透测试，也不保证 Windows Shell 扩展或运行时不存在漏洞。

## 验证方法

- 使用本机现有 .NET 8 SDK 构建。
- 最终回归结果：35/35 通过；Release 发布成功。桌面 76 个文件重新扫描后，图案边界面积低于画布 50% 的图标从 1 个降为 0 个。
- 新增无测试框架依赖的 `tests/DeskFlow.Regression` 控制台回归程序，并加入解决方案。
- 测试覆盖：图标透明留白、普通图标边距、非正方形比例、半透明颜色、100/150/200% DPI、缓存失效、路径限制、实际临时文件重命名、规则覆盖与兜底、批量拖入、增量变更、配置恢复/备份保护/失败反馈、循环日期与父链修复、真实 FileSystemWatcher 事件。
- 使用真实 `kenshi_x64.exe - 快捷方式.lnk`，通过生产图标提取路径验证并保存前后 PNG。
- 所有测试写入独立临时目录；不通过主程序的 smoke-test 修改真实桌面或自启设置。
- 纯分类示例：10,000 个条目、8 条默认规则单次测量约 9ms。该结果不包含磁盘扫描、图标提取和 WPF 渲染，不可作为整桌面性能承诺。

这里只验证了进程持续运行、配置数量与生产图标提取结果，未代替完整的多屏手工交互验收。

## 尚未关闭的风险与限制

1. **Shell 异常与强制终止**：P1 已加入桌面显隐消息超时、独立恢复守护、手动恢复入口，完成隔离故障测试。整机断电、同时终止主进程与守护、第三方 COM/慢磁盘仍有限制，详见 [P1 系统可靠性](P1-系统可靠性.md)。
2. **混合 DPI 实屏验证**：P1 已切换为显示器内相对坐标，加入首选回收屏与断屏回收。当前机器仅检测到一台显示器；100/150/200% 混合屏、负坐标副屏和热插拔仍需实屏校准。
3. **大文件量 UI**：普通 WrapPanel 不虚拟化；单个盒子包含数千文件时仍会创建大量视觉元素。增量处理减少刷新范围，但不解决盒内所有视觉节点的成本。
4. **手动路径与监听范围**：桌面外文件可以被引用，但仅桌面目录被实时监听；外部路径重命名/删除的同步仍有限。监听丢事件后的全量补扫无法可靠还原已经丢失的重命名身份。
5. **设置窗口并发变化**：P1 已加入设置草稿及基于基线和最新配置的字段合并。未运行回归测试；同一个设置字段被多个来源同时改写的优先级仍以用户本次明确改动为准。
6. **老自定义规则**：本轮只改变新添加规则的优先级。旧配置原有顺序保持；后续提供可视化规则排序与命中解释，避免擅自改动用户规则含义。
7. **错误诊断**：P1 已接入统一本地滚动日志与托盘入口；诊断包导出尚未实现。
8. **构建警告**：现有 WPF + WinForms 混用产生 WFAC010 DPI 配置警告。应结合真实多屏测试再统一 manifest 与 WinForms DPI 初始化，不直接删除声明。
9. **配置扩展**：P1 已增加配置版本迁移、备份恢复入口和历史/快照清理。待办历史和快照仍集中在一个 JSON 内；更大数据量时仍可考虑拆分存储。
