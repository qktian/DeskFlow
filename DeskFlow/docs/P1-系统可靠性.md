# P1 系统可靠性实现与验收

日期：2026-10-04。范围为优化计划中的「P1｜系统可靠性」，不包含设置草稿、多屏坐标重构。

## 已实现

| 项目 | 行为 |
|---|---|
| 桌面 Shell 控制超时 | 显隐命令通过 SendMessageTimeout 发送，单次等待 250ms；退出时最多 4 次、间隔最多 250ms。每次重新寻找桌面窗口，窗口被重建时不复用旧句柄。未找到桌面不再误报隐藏成功。 |
| 异常退出恢复 | 隐藏前启动同目录 DeskFlow.exe 的独立守护模式，握手成功才隐藏。守护进程等待主进程结束后恢复图标；PID 与进程启动时间一起校验，防止 PID 重用。 |
| 恢复并发保护 | 恢复记录包含随机会话标识，通过命名互斥量串行读取、替换和恢复。旧守护进程不能覆盖新会话；正常恢复清理记录，守护进程自行退出。 |
| 故障降级 | 守护进程启动失败时暂停隐藏并提示。Explorer 未就绪时守护最多尝试 20 次，间隔 500ms；失败保留记录、写入日志，可稍后手动恢复。 |
| 退出与关机 | 恢复图标优先于其他资源释放，每个清理步骤独立捕获并记录异常。关机会话处理等待 UI 调度最多 3 秒，失败后尝试直接恢复。 |
| 异常处理 | UI 未处理异常记录日志、恢复图标并安全退出，避免继续运行半初始化状态；记录进程与后台任务未处理异常。 |
| 滚动日志 | `%AppData%\DeskFlow\logs\deskflow.log`，默认单文件约 1MiB，保留 3 个滚动备份。跨进程互斥写入，日志故障不向业务抛出异常。 |
| 热键冲突 | 保存前整组验证格式、重复组合、系统保留键及实际占用。新注册失败则撤销临时注册、保留原热键；支持操作之间交换热键、留空禁用；抑制按住时重复触发。启动冲突通过托盘提示，仍尝试启用其他可用热键。 |
| 恢复入口 | 托盘新增「恢复系统桌面图标」「打开诊断日志」。恢复会关闭当前隐藏设置并保存；已打开的设置窗口取消时不会撤销这次恢复。 |

日志覆盖启动、退出、配置加载/备份/保存、监听错误、热键注册、鼠标钩子安装、自启设置、桌面控制和恢复流程。异常堆栈可能包含本机路径，日志仅存本地。

## 使用与排障

运行中的程序可从托盘恢复；程序已退出时可运行：

```powershell
.\DeskFlow.exe --recover-desktop
```

有实例时此命令通知主实例关闭隐藏策略并保存；无实例时只恢复图标，不启动盒子或改写桌面配置。正常更新使用 `--exit`，等待主进程和守护进程退出后再覆盖发布文件。

启用隐藏时任务管理器会出现两个 DeskFlow 进程，其中带 `--watch-owner` 参数的是恢复守护进程，不显示窗口。它不扫描桌面、不创建托盘或盒子；主进程退出或恢复记录被清理后结束。

## 自动化验收

`tests/DeskFlow.Regression` 共 **65/65** 项通过（含真实 Kenshi 快捷方式的 3 档 DPI 检查）。新增 13 项系统可靠性检查：

- 日志轮转数量和大小、并发写入、无写权限/无效目录降级与清理故障隔离。
- 热键格式、实际原生注册冲突、失败保留旧注册和释放临时注册、交换操作、禁用、重复键和保留键。
- 独立窗口线程阻塞 1.8 秒，设置 100ms 超时后实际约 103ms 返回；销毁窗口后失败、新窗口可重新响应。
- 旧会话不能恢复新会话、失败保留记录、PID 重用保护、暂时未就绪后重试成功。
- 模拟 Explorer 持续不可用时 20 次重试后退出，恢复记录保留。
- 独立测试进程被强制结束后，另一个测试守护进程执行恢复；正常恢复后守护退出而主进程仍存活。

测试使用独立临时目录、原生测试窗口和测试进程。只短暂占用空闲的 Ctrl+Alt+Shift+F13～F24 组合并释放；不终止真实 Explorer，不隐藏真实桌面图标，不执行真实关机，不修改用户配置/注册表。

运行命令：

```powershell
dotnet run --project tests/DeskFlow.Regression -c Release
dotnet run --project tests/DeskFlow.Regression -c Release -- 'C:\path\sample.lnk'
```

## 验证边界

- Explorer 重启通过窗口销毁/重建和恢复重试进行隔离验证；没有在用户工作期间主动重启 Explorer 或关机。关机/注销整机流程仍需在可中断的测试会话验收。
- 主进程和守护进程同时被终止、断电或系统崩溃时，无法保证立即恢复；重新运行程序或 `--recover-desktop` 可以再次恢复。
- 本项有界调用针对原先会阻塞 UI 的桌面显隐 SendMessage。第三方 Shell 扩展的图标 COM 提取仍使用后台 STA；文件打开、回收站和慢磁盘操作尚未全部实现独立进程隔离。本轮不声称所有 Windows Shell 行为都有硬超时。
- 关机 UI 调度等待和桌面消息等待有界，配置落盘仍受实际文件系统响应影响。
- 原有 WPF/WinForms 的 WFAC010 DPI 警告保留，交由 P1 多屏体验统一处理。

原生接口依据：[SendMessageTimeoutW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw)、[RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。超时测试使用不同线程的窗口，避免同一消息队列的超时参数不生效。
