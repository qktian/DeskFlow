# P2 性能、归类、搜索与快照

## 已完成

- 盒内图标改为按行虚拟化；WPF 仅生成可见区附近的行，条目进入可视区域才请求 Shell 图标。调整盒宽时重排列数，保留当前条目列表。
- 启动和监听溢出的全量桌面扫描在后台执行；整理也在后台扫描后回到 UI 线程应用。扫描结果采用版本号避免旧结果覆盖新状态，整理期间的监听补扫延后处理。
- 文件元数据缓存 30 秒并按监听事件失效，最多保留 10,000 项；图标缓存按约 64 MiB 位图字节预算和 5,000 条目上限做 LRU 淘汰，提供命中、未命中和淘汰统计。
- 规则可上移/下移、编辑名称关键词，保存规则后可预览当前桌面条目的预计归属变化。条目右键可查看命中依据；Ctrl/Shift 多选、盒内全选，支持批量移动和移出。
- 一键整理可撤销上一次归属变化；撤销状态仅保留在当前运行会话中。托盘和盒子菜单均可执行撤销。
- 托盘新增已收纳条目的离线搜索，按文件名、路径和盒子名称过滤，支持打开和在资源管理器中显示；不扫描其他目录，也不连接网络。
- 快照兼容旧格式，同时保存盒子的位置、尺寸、屏幕、折叠、置顶、图标尺寸、排序和外观，以及待办面板的位置、尺寸、屏幕、折叠、自适应高度和外观。恢复时仍跳过不存在的文件，并把越界窗口拉回可见屏幕。

## 基准

执行 `dotnet run --project tests/DeskFlow.Regression -c Release -- --benchmark`。基准在临时目录建立 100、1,000、5,000 个空文件，分别测冷/热元数据扫描、透明测试盒子的首次渲染调度、WPF 已生成行数、托管堆占用和首次 220ms 内超过 50ms 的 UI 定时器间隔。运行顺序固定，首个样本包含更多 WPF/JIT 预热成本；数字用于复测对比，不代表所有电脑的首屏承诺。

| 文件数 | 冷扫描 | 热扫描 | 元数据命中率 | 首次渲染 | 已生成行 / 总行 | 托管堆 | UI 间隔 >50ms |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 100 | 18.0ms | 4.2ms | 50% | 301.8ms | 34 / 34 | 3.8MiB | 1 |
| 1,000 | 108.6ms | 31.8ms | 50% | 355.3ms | 45 / 334 | 5.6MiB | 1 |
| 5,000 | 461.7ms | 116.8ms | 50% | 191.8ms | 45 / 1,667 | 8.7MiB | 1 |

缓存命中率是冷扫一次、热扫一次的合计，因此理论上接近 50%。5,000 文件时仅生成 45 / 1,667 行，图标提取量不随总条目数线性增长。仍有一次首帧阶段超过 50ms 的间隔；后续若要进一步降低首帧耗时，应在真实桌面设备上用 ETW/Visual Studio 分析 WPF 模板创建与透明窗口合成。

## 边界

旧快照只有文件归属，没有布局字段，恢复旧快照时保留当前布局。新快照恢复现存盒子和待办面板的布局；已删除的面板不会重新创建。待办开启高度自适应时，恢复后高度仍会根据当前任务内容重算。搜索范围仅限现有盒子中的路径，不搜索未收纳或其他磁盘文件。撤销整理不包含文件内容修改、删除或重命名。
